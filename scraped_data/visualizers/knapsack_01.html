Core Idea

The 0/1 Knapsack problem asks: given items with weights and values, select items to maximize value without exceeding capacity. Each item is either fully included (1) or not included (0)—no fractional items allowed. This is a perfect case for Dynamic Programming because decisions repeat across many subproblems.

📋 Problem Statement With Example

You have:

• Item 0: weight=2, value=3
• Item 1: weight=3, value=4
• Item 2: weight=4, value=5
• Knapsack capacity: 5

Question: What is the maximum value you can fit?

✓ Answer: Take item 0 (weight=2, value=3) + item 2 (weight=4, but only 3 left... can't fit).
✓ Better: Take item 0 (weight=2, value=3) + item 1 (weight=3, value=4) = total weight 5, value 7. ✓ OPTIMAL!

  • Decision: for each item, make two choices: include it (if it fits) or skip it.
  • Overlapping Subproblems: decisions like "best value using items starting at index 1 with capacity 5" appear multiple times in different branches.
  • Optimal Substructure: best solution for (i, w) = max of (skip item i) or (include item i + best for remaining items).
  • DP State: dp[i][w] = maximum value using first i items with capacity w.
  • Recurrence: dp[i][w] = max(skip, include) where skip = dp[i-1][w] and include = dp[i-1][w-weight[i]] + value[i].
  • Result: Without DP, time is O(2^n); with DP, it drops to O(n·W) where W is capacity.

1) State Definition

dp[i][w] = best value using first i items with max capacity w.

2) Two Choices

Skip item i, or include it. Choose the option that gives higher value.

3) Base Cases

dp[0][w] = 0 (no items = 0 value). dp[i][0] = 0 (no capacity = 0 value).

Approach In Plain English

Recursive Approach (Without DP)

What Each Recursive Call Means:

knapsack(i, w) = "What is the maximum value I can get starting from item i with remaining capacity w?"

• i: Current item index (0 to n-1). We decide about this item first, then move to next.
• w: Remaining knapsack capacity (0 to capacity). After including an item, capacity shrinks.

How the Approach Works:

  • At item i with capacity w: we must decide: include item i or skip it?
  • Skip choice: ignore item i, keep capacity w → knapsack(i+1, w)
  • Include choice: if item i's weight ≤ w, take it (gain value) → value[i] + knapsack(i+1, w-weight[i])
  • Return: the maximum of skip and include branches.
  • Base cases: if i ≥ n (no items left) or w = 0 (no space), return 0.
  • Problem: knapsack(1, 5) may appear 100+ times across different paths—massive redundant work!

DP Memoization Approach

Same Logic, But With Memory:

We make the same recursive calls, but we never compute the same (i, w) pair twice.

  • Before recursing: check memo: "Have I solved knapsack(i, w) before?"
  • Cache hit: yes! Return stored answer instantly (no recursion needed).
  • Cache miss: no, solve it like before (skip and include branches).
  • Store result: save memo[(i, w)] = answer before returning.
  • Unique states: only n × (capacity+1) unique (i, w) pairs exist.
  • Advantage: O(2^n) recursion becomes O(n·W) with huge speedup!

Pseudocode And Complexity

Pseudocode (DP Memoization)

function knapsack_dp(i, w, memo):
    if (i, w) in memo:
        return memo[(i, w)]
    if i == n or w == 0:
        return 0
    skip = knapsack_dp(i+1, w, memo)
    include = 0
    if weight[i] <= w:
        include = value[i] + knapsack_dp(i+1, w-weight[i], memo)
    memo[(i, w)] = max(skip, include)
    return memo[(i, w)]

main:
    memo = empty map
    answer = knapsack_dp(0, capacity, memo)
  • Memo lookup: avoids recomputing same (i, w) pairs.
  • Base cases: no items left (i==n) or no capacity (w==0) → return 0.
  • Recurrence: max of skip and include transitions.

Time / Space Complexity

Without DP recursion:
Time  : O(2^n)   (every item, pick or skip)
Space : O(n)     (recursion depth)

With DP memoization:
Time  : O(n·W)   (unique states: n items × W capacities)
Space : O(n·W)   (memo map + recursion depth)

With tabulation:
Time  : O(n·W)
Space : O(n·W), can be optimized to O(W)
  • State count: exactly n·(W+1) unique (i, w) pairs.
  • Real speedup: O(2^n) → O(n·W) is massive for large n.
  • Trade-off: added space for memo is worth the time savings.

def knapsack(weight, value, capacity):
    n = len(weight)
    
    def knapsack_rec(i, w):
        if i == n or w == 0:
            return 0
        skip = knapsack_rec(i + 1, w)
        include = 0
        if weight[i] <= w:
            include = value[i] + knapsack_rec(i + 1, w - weight[i])
        return max(skip, include)
    
    return knapsack_rec(0, capacity)

def knapsack_dp(weight, value, capacity):
    n = len(weight)
    memo = {}
    
    def dp(i, w):
        if (i, w) in memo:
            return memo[(i, w)]
        if i == n or w == 0:
            return 0
        skip = dp(i + 1, w)
        include = 0
        if weight[i] <= w:
            include = value[i] + dp(i + 1, w - weight[i])
        memo[(i, w)] = max(skip, include)
        return memo[(i, w)]
    
    return dp(0, capacity)
#include <stdio.h>
#include <string.h>

int knapsack_rec(int weight[], int value[], int n, int w) {
    if (n == 0 || w == 0) return 0;
    if (weight[n-1] > w)
        return knapsack_rec(weight, value, n-1, w);
    int include = value[n-1] + knapsack_rec(weight, value, n-1, w - weight[n-1]);
    int skip = knapsack_rec(weight, value, n-1, w);
    return (include > skip) ? include : skip;
}

#define MAX_N 20
#define MAX_W 100
int memo[MAX_N][MAX_W];

int knapsack_dp(int weight[], int value[], int n, int w) {
    if (n == 0 || w == 0) return 0;
    if (memo[n][w] != -1) return memo[n][w];
    if (weight[n-1] > w)
        return memo[n][w] = knapsack_dp(weight, value, n-1, w);
    int include = value[n-1] + knapsack_dp(weight, value, n-1, w - weight[n-1]);
    int skip = knapsack_dp(weight, value, n-1, w);
    return memo[n][w] = (include > skip) ? include : skip;
}

Line-by-Line Explanation

  • if (i, w) in memo: cache hit—return immediately without recursion.
  • if i == n or w == 0: base cases stop recursion and return 0.
  • skip = dp(i + 1, w): value if we don't take item i.
  • include = value[i] + dp(...): value if we take item i, plus recursion on reduced capacity.
  • memo[(i, w)] = max(...): store best result for this state before returning.
  • memo[n][w] != -1: check if state is already computed (non-negative value).
  • if (weight[n-1] > w): item too heavy, can only skip it.
  • include = value[n-1] + knapsack_dp(...): add current value and solve for remaining capacity.
  • memo[n][w] = ...: store the maximum (include or skip) before returning.
  • memset(memo, -1, ...): initialize array to -1 before calling DP function.

Key Insights

Why 0/1 Knapsack is a DP Classic

  • Overlapping subproblems: many paths in the tree lead to the same (i, w) state, making recursion wasteful.
  • Optimal substructure: the best solution for (i, w) is built from best solutions for (i+1, w) and (i+1, w-weight[i]).
  • DP brings exponential to polynomial: without memoization, we explore 2^n decision branches; with it, we solve only n·W unique states.
  • Interview favorite: tests understanding of DP state design, recurrence relations, and complexity analysis.
  • Real-world relevance: resource allocation, budget optimization, and selection problems all map to knapsack variants.
