Core Idea

The Rod Cutting problem asks: given a rod of length n and a price table for each length, find the maximum profit by cutting the rod into pieces. Unlike 0/1 Knapsack, pieces can be reused (unbounded)—you can make multiple cuts at the same position.

📋 Problem Statement With Example

You have:

• Length 1: price = 1
• Length 2: price = 5
• Length 3: price = 8
• Rod length: 3

Question: How to cut the rod to maximize profit?

✓ Option 1: No cut (one piece of length 3) = price 8.
✓ Option 2: Cut into three pieces of length 1 = 1+1+1 = 3.
✓ Option 3: Cut into one piece of length 1 + one of length 2 = 1+5 = 6.
✓ OPTIMAL: No cut = 8 (maximum profit)

  • Decision: for each length, try cutting at every position or not cutting at all.
  • Unbounded: unlike 0/1 Knapsack, we can use pieces of same length multiple times.
  • Overlapping Subproblems: decisions like "best profit for rod of length 2" appear multiple times in the tree.
  • Optimal Substructure: best profit for length n = max(price[n] directly, or cut at position i and use optimal profits of remaining pieces).
  • DP State: dp[i] = maximum profit from a rod of length i.
  • Recurrence: dp[i] = max(price[i], max(price[j] + dp[i-j])) for all valid cut positions j.
  • Result: Without DP, time is O(3^n); with DP, it drops to O(n²).

1) State Definition

dp[i] = best profit from rod of length i.

2) All Cuts Matter

Try every position to cut (unbounded). No restriction on reuse.

3) Base Cases

dp[0] = 0 (no rod = no profit). dp[i] = price[i] if no better cut.

Approach In Plain English

Recursive Approach (Without DP)

What Each Recursive Call Means:

maxProfit(n) = "What is the maximum profit from a rod of length n?"

• n: Current rod length (1 to original length). We decide where to cut or not cut.

How the Approach Works:

  • For rod of length n: we can cut at position i (1 ≤ i ≤ n) or not cut at all.
  • If cut at i: get price[i] + recursively solve for rod of length (n-i).
  • If no cut: keep entire rod and get price[n].
  • Try all: explore all possible first cuts and return maximum profit.
  • Base case: if n = 0 (no rod left), profit = 0.
  • Problem: maxProfit(2) may be computed 50+ times—massive redundant work!

DP Memoization Approach

Same Logic, But With Memory:

We make the same recursive calls, but we never compute the same length n twice.

  • Before recursing: check memo: "Have I solved maxProfit(n) before?"
  • Cache hit: yes! Return stored answer instantly (no recursion needed).
  • Cache miss: no, solve it like before (try all cut positions).
  • Store result: save memo[n] = answer before returning.
  • Unique states: only n unique lengths (0 to n) exist.
  • Advantage: O(3^n) recursion becomes O(n²) with huge speedup!

Pseudocode And Complexity

Pseudocode (DP Memoization)

function maxProfit_dp(n, memo, prices):
    if n in memo:
        return memo[n]
    if n == 0:
        return 0
    max_profit = 0
    for i from 1 to n:
        profit = prices[i] + maxProfit_dp(n - i, memo, prices)
        max_profit = max(max_profit, profit)
    memo[n] = max_profit
    return memo[n]

Time / Space Complexity

Without DP recursion:
Time  : O(3^n)   (branching factor ≈ 3 per level)
Space : O(n)     (recursion depth)

With DP memoization:
Time  : O(n²)    (each length: n iterations)
Space : O(n)     (memo for n+1 states)

With tabulation:
Time  : O(n²)
Space : O(n)
  • Why n²: for each length i, we try n-i cuts, giving Σ(i) = O(n²).
  • Huge speedup: O(3^n) → O(n²) is dramatic for larger n.
  • Unbounded advantage: DP is perfect for unbounded problems where items repeat.

int maxProfit_rec(int n, int prices[]) {
    if (n == 0) return 0;
    int max_p = 0;
    for (int i = 1; i <= n; i++) {

#define MAX_N 20
int memo[MAX_N];

int maxProfit_dp(int n, int prices[]) {
    if (memo[n] != -1) return memo[n];
    if (n == 0) return 0;
    int max_p = 0;
    for (int i = 1; i <= n; i++) {
        int profit = prices[i - 1] + maxProfit_dp(n - i, prices);
        max_p = (profit > max_p) ? profit : max_p;
    }
    return memo[n] = max_p;
}

Line-by-Line Explanation

  • if n in memo: cache hit—return immediately without recursion.
  • if n == 0: base case: no rod left means no profit.
  • for i in range(1, n+1): try cutting at every position (unbounded choices).
  • profit = prices[i-1] + maxProfit_dp(...): add cut value to optimal profit of remaining rod.
  • memo[n] = max_p: store best profit for this length before returning.
  • memo[n] != -1: check if length n is already computed.
  • if (n == 0): base case for rod length 0.
  • for (int i = 1; i <= n; i++): loop through all possible first cuts.
  • maxProfit_dp(n - i, prices): recursive call for remaining rod after cutting length i.
  • memo[n] = max_p: store result before returning to avoid recomputation.

Alternative Approach: Unbounded Knapsack Style (No For-Loop)

Second Formulation: Position-Based Decision Tree

Instead of looping through all positions, we can think of it as: at each recursion level, decide whether to cut at position i or skip it. This is the unbounded knapsack formulation where pieces can be reused.

maxProfit(n, pos) = "What's the maximum profit from rod of length n, considering only cuts at position pos and beyond?"

  • n: Remaining rod length
  • pos: Current position we're deciding to cut or skip (1 to n)
  • Choice 1 (Skip): Don't cut at pos, move to next position → maxProfit(n, pos+1)
  • Choice 2 (Cut): If pos ≤ n, cut at pos (unbounded—can reuse!) → price[pos] + maxProfit(n-pos, pos)
  • Base: if pos > n or n = 0, return 0
  • Unbounded key: in the cut option, we stay at pos (don't increment), allowing reuse!

    if (n, pos) in memo:

  • State: (n, pos) two dimensions now (length × position).
  • Skip branch: move to next position without cutting.
  • Cut branch: unbounded—stay at pos for potential reuse.

Time / Space Complexity (Approach 2)

Without DP recursion:
Time  : O(2^n)   (binary branching per state)
Space : O(n)     (recursion depth)

With DP memoization:
Time  : O(n²)    (unique states: n × (n+1)/2 ≈ n²)
Space : O(n²)    (memo for (n, pos) pairs)

Comparison to Approach 1:
Approach 1: O(n²) time, O(n) space
Approach 2: O(n²) time, O(n²) space
(Both asymptotically similar, but different structure)
  • States: sum over all (n,pos) pairs where 1 ≤ pos ≤ n.
  • Trade-off: position-based needs extra space but clarifies unbounded nature.
  • Practical: both are fine; choose based on problem intuition.

#include <string.h>

int maxProfit_rec_pos(int n, int pos, int prices[]) {
    if (pos > n || n == 0) return 0;
    int skip = maxProfit_rec_pos(n, pos + 1, prices);
    int cut = prices[pos - 1] + maxProfit_rec_pos(n - pos, pos, prices);
    return (skip > cut) ? skip : cut;
}

#define MAX_N 20
int memo_alt[MAX_N][MAX_N];

int maxProfit_dp_pos(int n, int pos, int prices[]) {
    if (memo_alt[n][pos] != -1) return memo_alt[n][pos];
    if (pos > n || n == 0) return 0;
    int skip = maxProfit_dp_pos(n, pos + 1, prices);
    int cut = prices[pos - 1] + maxProfit_dp_pos(n - pos, pos, prices);
    return memo_alt[n][pos] = (skip > cut) ? skip : cut;
}

Line-by-Line Explanation (Approach 2)

  • if (n, pos) in memo: cache hit—return immediately.
  • if pos > n or n == 0: base case—all positions considered or no rod left.
  • skip = maxProfit_dp_pos(n, pos + 1, ...): don't cut at pos, move forward.
  • cut = prices[pos-1] + maxProfit_dp_pos(n - pos, pos, ...): unbounded—reuse pos!
  • memo[(n, pos)] = max(...): store 2D state for future lookups.
  • memo_alt[n][pos] != -1: check if (n,pos) already computed.
  • if (pos > n || n == 0): base case exits recursion.
  • skip = maxProfit_dp_pos(n, pos+1, ...): increment pos when skipping.
  • cut = prices[pos-1] + maxProfit_dp_pos(n-pos, pos, ...): keep pos same for reuse!
  • memo_alt[n][pos] = ...: store 2D result in array.

Key Insights

Why Rod Cutting is an DP Classic

  • Unbounded choices: unlike 0/1 Knapsack, we can cut at ANY position, creating many more states and overlaps.
  • Optimal substructure: best profit for length n depends on best profits of smaller lengths (n-1, n-2, ... 1).
  • Exponential to polynomial: without DP, O(3^n) recursion; with DP, O(n²) is manageable even for n=100.
  • Real-world applications: cutting steel rods, lumber optimization, paper cutting—all use this principle.
  • Interview teaching tool: demonstrates unbounded knapsack concept and introduces DP recurrence design.
