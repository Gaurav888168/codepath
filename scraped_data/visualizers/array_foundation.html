Array Foundation

Explore 1D and 2D arrays interactively. Insert, delete, and access elements. Visualize memory layout, indexing, and the differences between 1D and 2D structures in C and Python.

Theory

An array is the most fundamental data structure — a contiguous block of memory that stores elements of the same type. Arrays provide O(1) random access using an index, making them extremely fast for read-heavy workloads. 2D arrays extend this concept to a grid (rows × columns), ideal for matrices and image data.

  • 1D Array: Linear sequence of elements at contiguous memory addresses. Access via single index: arr[i]
  • 2D Array: Grid of elements with row and column index: arr[i][j]. Stored in row-major order in C.
  • Time Complexity:
    • Access: O(1) — direct index calculation
    • Search (unsorted): O(n)
    • Insert/Delete at end: O(1); at middle: O(n)
  • Space Complexity: 1D → O(n); 2D → O(n × m)
  • Memory Address: For 1D: base + i × sizeof(type). For 2D: base + (i × cols + j) × sizeof(type)
  • Applications:
    • Storing sequences, lists, and buffers
    • 2D matrices for images, grids, game boards
    • Lookup tables and frequency counts

Approach

1D Array  Linear · Contiguous Memory

A 1D array is a fixed-size, ordered sequence of elements stored at consecutive memory addresses. Every element is the same type, so the CPU can jump to any element instantly using simple arithmetic.

Core Operations

  1. Access — Provide an index i. The CPU computes the address as base + i × size and reads directly. No traversal needed. O(1).
  2. Traversal — Visit every element from index 0 to n−1 in order, one step at a time. O(n).
  3. Insert at middle — To insert at index pos, shift every element from pos to end one step to the right, then place the new value. O(n).
  4. Delete at middle — Remove element at index pos, then shift every element after it one step to the left to close the gap. O(n).
  5. Append / Delete at end — No shifting required; simply place or remove the last element. O(1).

Key Insight

Arrays are fast at the edges (append/pop) and fast at random reads, but expensive in the middle — insertions and deletions force a chain of shifts. The larger the array, the worse the middle operations get.

2D Array  Grid · Row-Major Order

A 2D array is a grid of rows and columns. Internally, it is still stored as a flat block of memory — rows are laid out one after another (row-major order). You address each cell with two indices: arr[row][col].

Core Operations

  1. Access cell [i][j] — The CPU computes the flat offset as (i × cols + j) × size and reads it directly. Still O(1).
  2. Row traversal — Fix row i, iterate over all columns j = 0 … cols−1. Reads contiguous memory → cache-friendly. O(cols).
  3. Full traversal — Outer loop over rows, inner loop over columns. Visit every cell exactly once. O(n × m).
  4. Update cell — Access by [i][j] in O(1), overwrite the value. No shifting needed since the grid dimensions stay fixed. O(1).
  5. Column traversal — Fix column j, iterate over all rows. Reads non-contiguous memory (jumps by cols each step) → less cache-friendly. O(rows).

Key Insight — Row-Major Order

Even though you think in rows and columns, the computer stores all of row 0 first, then all of row 1, then row 2 — in one long flat sequence. Traversing row by row is always faster than column by column because it reads memory in order, keeping the CPU cache hot.
